# 静态累积法在既有动态录制上的测试

日期：2026-09-09；基线 `b6d1051b`，分支 `codex/visual-capability-loop-plan`。

## 结论

**当前静态累积法在本次三段动态录制上没有产生累积收益。** 全部420帧都未输出历史候选，融合深度与当前深度一致。动态颜色变化频繁触发整帧重置，算法实际退回当前帧处理；这既不是动态累积成功，也不能作为“历史复用没有残影”的安全证明。

本轮只增加旧录制评测入口、输入检查和动态风险诊断。`static_accumulator.py` 及CONFIG没有改变，正常供包、C++、分割和best配置不变；不修改任何数据集、审核状态或原始视频。

旧目录的深度是彩图配准后的毫米16位图，不是未配准原始深度。依据是原有 `runCaptureReplayDirectory()` 和bag转换路径：先配准到彩图，再换算毫米。新评测器直接读取旧格式，不制造内外参、硬件时间戳或 `PCS.RawStartupProbe/1`。

室内片段文件序号连续不等于相机从未漏帧，200ms时效在这里仅是30fps假设下的条件值。车载片段使用保存的数值时间戳，不被nominal参数覆盖；原流号/时间步长检查没有发现缺口，但未保存的时间域无法补证，不能确认跨流物理同步精度。车载case仍为 `reviewed=false`，只做诊断，不作为正式门禁或道路安全验证。

曾录制的普通AVI/MP4拼接画面不足以恢复16位深度，本次没有从深度伪彩图反推原始数值。原始车载bag仍是权威材料，本次只读其已有连续派生片段，没有重新录制或覆盖材料。

## 指标定义

- 重置帧：本帧与静态参考彩图比较触发整帧颜色重置。比例分母为主统计帧，不是变化像素数。
- 历史复用帧：至少一个像素的 `evidence_state=2`。历史像素按“像素×帧观测”计数，不代表不同物体数量。
- 可用状态翻转：相邻帧[0.3,3.5)m可用深度掩码的异或像素占全图比例，再取时间中位数；累积结果的对应指标允许历史候选参与。
- 局部颜色冲突：补入历史的位置，其当前颜色与来源帧同坐标颜色的任一通道差>20。这只用于已配准旧目录的诊断，不改变算法门禁，也不是物体真值。
- 重观测深度冲突：前帧使用历史的点，本帧重新获得有效观测，深度差超过原算法 `0.04+0.02*min(深度)` 门槛。仅是可能的旧表面滞留信号，传感噪声也可能触发。
- 探针耗时：仅Python `update()`及返回数组拷贝，排除读盘、哈希、检查、统计和导出；不是完整系统帧耗时或结果年龄。

## 结果

以下为排除前30帧后的统计。p95一栏先对每次运行取p95，再取三次的中位数，不是合并像素/帧后算出的值。

| 场景 | 颜色重置帧/统计帧 | 历史复用帧 | 原始→累积状态翻转 | 探针p95 |
| --- | ---: | ---: | ---: | ---: |
| 慢速平移 | 149/150，99.33% | 0 | 9.248%→9.248% | 24.31ms |
| 手部遮挡重现 | 84/90，93.33% | 0 | 5.875%→5.875% | 15.03ms |
| 车载连续运动 | 90/90，100% | 0 | 1.639%→1.639% | 13.08ms |

三次p95分别为：慢移24.31/24.59/23.95ms，手部15.83/15.03/13.64ms，车载13.08/12.75/13.08ms。不同片段和运行轮次的系统负载未严格隔离，也无置信区间，不用场景间速度差推导硬件性能因果。

全部帧复核同样没有历史候选：慢移178次颜色重置、手部113次、车载119次，各另有1次启动重置。因此不是仅后30帧统计窗口隐藏了历史复用事故。

车载主统计区间只有约0.989%图面有[0.3,3.5)m观测；大量道路目标不在这个近场探针的处理范围。该比例不能解读为车辆图像仅剩1%可见，也不能说剩余全是传感缺测：范围外观测、缺测与彩图归属要分别看。

## 原因验证

缓存保持区间包括重置时用当前值建立的第一帧。全片段最长区间分别为慢移2帧、手部3帧、车载1帧，而复用需要至少3次相容观测，且随后还须在未失效时出现可补缺测。

- 慢移主区间149帧同时超过全局平均色差和变化像素比例门槛；只有1帧不重置。
- 手部主区间84帧超过平均色差门槛，其中69帧也超过变化像素比例门槛。局部活动、曝光或阴影变化的影响没有被源分离，不能只归因于手本身。
- 车载主区间90帧同时超过两条颜色门槛，每帧都清空活动历史。

因此已有证据支持“整帧颜色否决导致缓存难以积累”的机制判断。但还没有完成局部遮罩对照或相机位姿补偿消融，不能断言单改某个阈值就会解决。

所有历史风险指标的历史样本数为0，相应冲突比例和年龄是 `null`，不是“0%错误”或“0ms滞后”。保存的风险样本选择按冲突/历史数量排序；因为全片均为0，三段都落在第0帧，不能将它们当成事故截图或代表性的动作关键帧。另人工查看了慢移第90帧、手部第60帧与车载第60帧原彩图，只用于确认材料内容，未制作物理真值标注。

## 验证与复现

新脚本 `PixelClusterSensor/evaluate_dynamic_accumulation.py` 保持独立旧格式入口。没有时间戳时必须显式提供 `--nominal-fps`；有时间CSV时按原记录读取，检查行键、有限数值、跨流数值时间差、源号和时间步长。错误格式、缺图、越界路径、超预算、时间行错位明确失败，不静默造新协议数据。

## 下一步

当前结论是“静态场景有效信号已见，动态复用未成立”，不是方案整体否定，也不是动态冠军。优先测试局部变化只使局部历史失效，未变化区域继续积累；相机移动则必须先有坐标对应/重投影，关联不可靠时保持降级。不要简单放宽全局门槛或无限延长缓存年龄。

后续需要回答：局部历史是否还对应同一表面？遮挡与背景重现时能否及时失效？应使用有真实时间证据、独立边界/对象标注的动态数据来评判，再讨论C++影子接入和正常供包。
