# 原始RGBD启动与帧间变化验证

日期：2026-09-09。基于 `314787f8`，分支 `codex/visual-capability-loop-plan`。范围为PixelClusterSensor的原始诊断、只读元数据与离线判据；不调整分簇、补全、旧主工程、驱动/注册表或best。

## 结论

**诊断工具链通过，实机联合稳定门禁未通过。** 三次各120帧共360帧已保存并经SHA256独立读取。每次首帧后SDK复用了1次彩图，正常源门禁拒绝，诊断记录该事件后继续；没有把拒绝和缺口隐藏成连续成功。

现场后段彩图变化较小，而深度差随距离明显增大。等待可以避开部分启动缺测过渡，但本次数据不支持“只要预热完成，每个像素深度就会基本相同”。固定30mm的全画面深度差门槛被持续触发，不能据此混淆“还在启动”与“运行中的噪声”。也不能反过来把门槛改大后宣布传感器稳定。

## 实施内容

1. `--probe-startup` 复用Source取原始RGBD，不分割/配准/插值，采集时不写PNG，源关闭后写完整原始帧；缓冲和采集预算有界。新格式保留逐流帧号及异常，提前EOF仍保存部分证据。
2. 源信息增加逐流SDK元数据。支持性与原始字符串值分开，缺失为null；不读取设置值冒充该帧实际曝光。
3. 离线 `analyze_startup.py` 计算窗口状态、全帧/4x4空间分区、缺测翻转、共同有效点深度差、RGB差、距离分带。输出不回写设备或观察包。
4. 合成反例覆盖全缺测、移动孔洞、局部变化抵消全局比例、颜色/深度/曝光变化、序列中断、时间窗、饱和值、距离归因、原始材料保留和EOF。

## 固定判据

以下阈值在本次真实采集前写入测试脚本，是实验假设，不是设备精度规范；实拍后只增加失败归因，不调整这些阈值。全部通过也只产生“变化较小候选”。

| 项目 | 判据 |
| --- | --- |
| 窗口 | 15对帧，即16帧；彩图时间跨度400至1000ms |
| 连续性 | 两流帧号分别+1、各自同域且时间递增；窗口内部无拒绝事件 |
| 有效性 | 每帧原始有效深度至少20%；每对共同有效点至少1000 |
| 全帧有效比例跨度 | 不超过2个百分点 |
| 4x4分区有效比例跨度 | 各区不超过5个百分点 |
| 每对有效/缺测状态翻转 | 不超过全像面2% |
| 每对共同有效点绝对深度差p95 | 不超过0.03m |
| RGB平均绝对差 | 不超过3/255码值 |
| RGB任一通道差大于20的像素 | 不超过2% |
| 有曝光/增益元数据时 | 窗口内不变化；缺失不假定已验证 |

0及65535始终无效；不参与深度数值差，但参与缺测翻转。距离分带按前一帧原始深度分组，只比较两帧均有效点；失去深度的点另计翻转，不伪造距离。分带统计只是定位，不用于绕过联合门禁。

## 实拍结果

同一设备D455（215122256633，固件5.14.0），RGBD各640x480@30。原始读取不包含后续图像处理和PNG写盘。三次分别重开，场景为桌面、椅子、柜体和墙面，未获得独立的相机姿态或绝对静止真值。本次场景与前轮人体场景不同，缺测率不能跨轮作算法比较。

| 指标 | 第1次 | 第2次 | 第3次 |
| --- | ---: | ---: | ---: |
| 接受帧数 | 120 | 120 | 120 |
| 首帧原始缺测比例 | 69.750% | 69.562% | 68.529% |
| 末30帧缺测比例中位数 | 30.946% | 30.981% | 30.969% |
| 拒绝旧帧事件 | 1 | 1 | 1 |
| 联合门禁候选窗口 | 0 | 0 | 0 |
| 仅深度差门槛未通过的窗口 | 67 | 76 | 101 |
| 末30对全场深度差p95的中位数 | 53mm | 53mm | 53mm |

各会话窗口状态均为积累中15、序列中断1、变化中104。其余“变化中”窗口还受缺测翻转或局部有效比例变化影响；没有强行选出赢家。

距离分层，末30对帧分别计算p95后再取中位数：

| 前帧深度分带 | 第1次 | 第2次 | 第3次 | 含义 |
| --- | ---: | ---: | ---: | --- |
| 0.3-1m | 7mm | 7mm | 7mm | 每对约1.45万至1.52万共同有效点 |
| 1-2m | 36mm | 37mm | 37mm | 每对约11.6万至11.8万点 |
| 2-3.5m | 73mm | 72mm | 72mm | 每对约7.7万点 |
| 大于等于3.5m | 1.399m | 6.185m | 5.137m | 仅约441至596点，含极端跳变，不能当可靠远距证据 |

这些不是绝对深度误差，也不是毫米级真值精度证明。不同分带观察的是不同表面，距离、材质、角度、边界和曝光条件尚未受控，因而只确认“本次分带统计不同”，不把所有差异都归因于距离。

第一会话最后10对RGB平均绝对差约1.87至2.05码值，通道差超过20的像素约0.001%至0.003%；共同有效深度差中位数约9mm，而p95约51至57mm。彩图低变化与深度波动同时存在，说明仅检查颜色稳定或总有效率不足以代替深度一致性检查。

## 原因边界

- 启动阶段确有大的缺测过渡及一次复用旧彩图；计数、原生帧号与拒绝原因已保存。
- 持续读取后仍有分距离的深度波动，倾向于运行噪声/边界与匹配问题，不只是算法写盘的影响：诊断采集时这些处理均未运行。但4秒左右的序列不能排除更长时热稳定或微小运动。
- SDK不提供Actual Exposure、Gain Level、Auto Exposure、Frame Timestamp、Sensor Timestamp；只提供后端时间、到达时间和Actual Fps等。后两类宿主相关时间不能替代真实曝光时间。未启用任何注册表修补，不声称已确定曝光收敛原因。
- 没有独立真值，不能从重复观测自证物理距离正确，不能把低变化但错误的数值升格为事实。
