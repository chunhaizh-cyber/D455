# PixelClusterSensor T3 进入期增长关联探针

日期：2026-09-22。分支：`codex/visual-capability-loop-plan`。

## 问题与边界

真实 `T3_local_motion` 60帧开发片段中，手臂进入画面时轮廓面积快速增长。普通关联虽有较高的较小包围矩覆盖率和相近颜色，但 IoU 代价超过未确认候选默认门槛 `200000/1000000`，导致进入阶段反复新建相机候选编号。

该探针只改善相机本地短期候选连续性，不创建现实存在身份，不证明所选轮廓等于完整手部，也不把历史回放写成当前世界事实。输入清单 SHA256 为 `655c498113c7fc2de41d032acd5c1cde4bc8bc2a5cb9fa1acb6b4e39571925d5`。

## 实现

新增默认关闭开关 `--allow-tentative-growth-association`。增长关联必须同时满足：

- 轨迹仍为 `Tentative`；
- 中心位移不超过画面对角线的12%；
- 像素面积比为0.25至4.0，且至少增长到1.25倍或收缩到0.85倍；
- 两个包围矩交集至少覆盖较小包围矩的75%；
- RGB均值归一化差不超过0.15；
- 前后候选像素数均至少为新候选准入门槛的3倍。

关联证据使用 `bbox-contained-growth-assignment/1`。该特例允许更新下一帧关联参考并保持候选编号，但会重置确认命中数；增长结束后必须重新取得完整的连续普通命中，不能仅靠增长链或增长前后的非连续命中晋级 `Active`。输出指标记录开关和本帧触发次数。

## 验证结果

合成测试确认：默认关闭时行为不变；受控增长保持编号；高代价平移、不同颜色大区域吞并和低于三倍准入门槛的小碎片均被拒绝。

真实 T3 开发片段对照：

| 指标 | 默认基线 | 增长探针 |
| --- | ---: | ---: |
| 活动帧对数 | 43 | 43 |
| 有候选重叠活动帧数 | 31 | 31 |
| 全阶段候选号种类 | 9 | 4 |
| 相邻活动样本换号 | 9 | 4 |
| 最长同号连续样本 | 15 | 15 |
| Active候选号种类 | 3 | 3 |
| Active命中帧数 | 19 | 18 |
| Active主导号占比 | 84.21% | 83.33% |

最终探针在第11、12、13、14、17帧维持主候选增长链，另在第13帧维持一个并行局部片段。六次增长关联均保持 `Tentative` 并重置确认累计。全阶段换号明显下降，但目标在增长结束后延迟取得 `Active`，因此 Active 命中少1帧；这项取舍必须由独立留出片段继续验证。

真实静态保存快照 `600x3` 离线复算中，三轮探针触发均为0；每轮生命周期均为 `Added=127`、`Removed=121`、`Occluded=0`、`Lost=0`、`Reappeared=0`，最终6个已激活候选，与默认路径一致。

## 决策

该实现保留为开发探针，默认关闭。它已通过开发片段和静态退化检查，但尚未通过独立 T3 留出片段。下一门槛是录制不参与阈值形成的真实局部运动片段，按同一诊断器比较候选号种类、换号、Active主导占比和视觉叠加；留出失败时不得继续收紧到开发片段特征。
