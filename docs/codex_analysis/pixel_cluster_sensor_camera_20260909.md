# PixelClusterSensor 真实相机调试记录

日期：2026-09-09。基于 `83af3687`，分支 `codex/visual-capability-loop-plan`。只调整新子工程的启动采集门禁及验证工具；未改 `D455.cpp`、分割/补全算法、成像参数、已有候选或best。

## 结论

实机供包和控制生命周期烟测通过，**不等于真实分簇质量或实时性能验收通过**。最终6次设备会话、30份真实RGBD观察包全部通过独立读回，包括全像面颜色重建、像素成员、轮廓目录、深度来源及标定重投影。

仍存在启动深度缺测偏高、同一人体拆成多个观察区域、部分图像候选可能跨对象、写盘供包不能保全30Hz源帧等问题。正式自我接收、世界身份、物理穿孔判定、运动曝光同步和绝对测距尚未验收。本轮不运行旧候选评分矩阵，不作性能改善或候选晋级声明。

## 故障复现与修复

原客户端3帧实拍在第一次 `获取单帧观察` 失败，代码为 `unsynchronized_frame`。补出时间诊断后，首次失败两流均为SDK `System Time`：彩图1788916090113.35ms，深度1788916089881.988ms，相差231.362ms。旧逻辑直接取SDK交来的第一对帧，遇到启动不相容即结束本次请求；保持设备打开后的9次新请求可以成功，支持“启动配对过渡”的判断，尚不证明具体是哪一层驱动/曝光导致时间差。

修复只作用于首帧配对尚未通过的阶段：共用一次1000ms等待预算，筛除缺流、旧帧、时间域不同、非有限时间戳或差值超过50ms的帧对；超过预算明确失败。通过首帧后恢复严格拒绝，不无限等待、不自动重开、不放宽时间门槛，也不改写时间戳。诊断保留累计拒绝数和最近拒绝帧对。逐帧预热状态仍为“未证明稳定”。

最终6次打开各筛除了6对启动帧；最近被拒绝帧对时间差约425.709至432.104ms，首份通过的彩图源帧号均为9。通过后的30包时间差11.606至21.199ms，时间域均为 `System Time`。这证明原型输入门禁得到遵守，**不证明真实曝光已同步到该误差**；后续需要原生传感器时间/元数据核查。

## 性能和缺测观察

以下为同一现场、短时烟测，没有冻结静态目标、没有独立真值或置信区间。计时只用于定位成本，不能与旧 `frame_metrics.csv` 全帧耗时等同。

| 指标 | 最终值 |
| --- | ---: |
| 30包仅算法处理 p50 / p95 / max | 35.160 / 84.690 / 117.760ms |
| 后续24包仅算法处理 p95 / max | 47.109 / 48.023ms |
| 实时优先20包仅算法处理 p95 / max | 47.279 / 48.023ms |
| 单帧调用往返 p50 / p95 / max | 659.610 / 743.696 / 748.268ms |
| 30包簇数量 min / p50 / max | 243 / 291 / 363 |
| 全部包原始无效深度比例 p50 | 42.673% |
| 全部包配准后缺测比例 p50 | 47.209% |
| 6份会话首帧原始无效深度比例 p50 | 74.403% |
| 后续24帧原始无效深度比例 p50 | 42.626% |

单帧往返样本中多数为重新打开后的首帧，因此包含启动等待，不能解释成常态每帧算法耗时；算法处理又不含等待、PNG编码、散列、文件写出和读回，不能用其倒数宣称实际输出FPS。实时优先20份包约16包/秒，源信息累计报彩图/深度各18个缺口（相对上一份被源接受的帧，包含任务起点边界），不能称完整30Hz序列。

原始0/65535深度已经缺失的部分不是后续分割删掉的；最近像素中心配准、视野/遮挡与采样竞争又会增加彩图像面缺测。原始图与彩图使用不同像面，不能把两个百分数之差逐像素解释为某一种配准错误。插值仍受小面积、同簇、颜色和深度一致门禁约束，不能为了降低缺测率把所有空白填满。

实拍图的定性复核显示：人体被分成头部、手臂/衣物等多个区域，另有大面积图像候选。深度缺测没有删除彩图像素，但同一对象完整轮廓、接触对象的分离和跨帧身份仍未形成验收证据；不能把零重建差异作为这些能力的证明。
