# D455 视觉方法需求—任务—学习—晋级闭环详细设计

## 一、文档定位

本文是《需求特征值方法流程说明》的上层治理设计，回答四个问题：

1. 真实失败如何形成一条去重后的视觉需求。
2. 需求如何被筹办成一个只有一个主目标的任务。
3. 任务如何选择、练习、组合和验证方法。
4. 方法如何按适用条件晋级、回退，并影响下一次运行。

本文目前是设计规格，不代表当前 D455 已经具备自动需求生成、自动任务调度或自动晋级代码。当前仓库已经具备确定性回放、分析包、特征表、评分和候选筛选基础；需求库、任务库、正式方法库和方法生命周期仍需后续实现。

本文中的中文名称是概念层名称。现有 C++ 源码仍使用英文符号，不能把本文的中文方法名误认为已经完成源码重命名。

## 二、总边界

视觉系统必须区分“现实是什么”“我观察到了什么”“我当前认为是什么”和“某个方法是否有效”。方法可以改善观察证据和认知状态，不能修改现实特征，也不能把推测直接写成世界事实。

| 层级 | 内容 | 可以做的事 | 不能做的事 |
|---|---|---|---|
| L0 现实材料 | 彩图、深度、左右红外、姿态和时间 | 提供传感器输入 | 不能由算法改写 |
| L1 观察材料 | 深度锚点、彩色轮廓、双目证据、候选簇、像素账本 | 记录来源、置信度和缺失 | 不能直接等同于已确认存在 |
| L2 认知状态 | 目标候选、轮廓跟踪、遮挡关联、当前距离模式 | 从未知逐步迁移到候选、稳定、已确认 | 不能用历史预测冒充当前传感器事实 |
| L3 方法能力 | 方法版本、适用条件、失败回执、成本和证据 | 通过任务复验后晋级或回退 | 不能只凭单次总分成为全局能力 |
| L4 实验治理 | 需求、任务、运行、评分、晋级记录 | 组织练习和复查 | 不能把报告结论当成现实对象 |

当前 D455 主要覆盖 L0、L1 和部分 L2 的输出与测量；本文的 L3、L4 是下一阶段治理骨架。

## 三、核心概念

### 3.1 需求

需求只表达稳定、可证据化的差距，不直接指定实现方法。

一条需求至少包含：

| 字段 | 含义 |
|---|---|
| 需求编号 | 去重后的稳定标识 |
| 目标主体 | 受影响的对象、像素账本、观察簇或运行质量 |
| 目标特征 | 需要改善的特征，例如轮廓连续性、远场保留、帧耗时 |
| 当前特征值 | 在固定运行和帧范围内观测到的值 |
| 目标特征值或值域 | 要达到的值、区间或状态 |
| 差距证据 | 运行编号、配置、提交版本、帧号和事件 |
| 来源因果 | 触发差距的可验证原因，允许为候选原因 |
| 满足条件 | 硬门槛、软指标、适用场景和禁止退化项 |
| 生命周期状态 | 候选、已确认、处理中、已满足、暂未满足、关闭 |

需求不能写成“把 ROI 调小”“改成多线程”这类方法命令。正确写法是“局部运动时，轮廓刷新区域过大，导致帧耗时超过门槛；在不增加丢失和误删的条件下，需要降低刷新区域和最坏帧耗时”。

### 3.2 任务

任务是对一条需求的一次受控处理过程。一个任务只有一个主要目标，其他指标作为硬约束或禁止退化项。

| 字段 | 含义 |
|---|---|
| 任务编号 | 一次可追溯的处理编号 |
| 来源需求编号 | 任务所承接的需求 |
| 主目标 | 本次只允许优化的一个核心特征 |
| 输入材料句柄 | 固定回放、训练帧、验证帧和在线影子数据 |
| 当前基线方法 | 作为对照的已登记方法版本 |
| 候选方法集合 | 最多三个受控候选及其参数差异 |
| 资源预算 | 最大运行次数、帧数、时间和线程资源 |
| 验证合同 | 硬门槛、软指标、G3 等专项门禁 |
| 回退条件 | 任何导致任务停止或回到基线的条件 |
| 任务状态 | 筹办、练习、尝试、定向学习、复验、影子、完成、失败 |

任务不能直接宣布需求满足。只有候选方法完成固定回放、留出回放和必要的在线影子验证，且晋级记录成立，需求才可以迁移到“已满足”。

### 3.3 方法

正式方法不是任意一个内部函数，而是可以被任务查询、绑定输入、执行、产生失败回执并接受验证的能力单元。

方法合同至少包含：

| 字段 | 含义 |
|---|---|
| 方法编号与版本 | 稳定身份和可回退版本 |
| 中文方法名 | 面向需求和任务的概念名称 |
| 方法类型 | 原子方法、复合方法、实验治理方法 |
| 适用条件 | 场景、运动状态、证据状态、距离范围和资源条件 |
| 输入证据 | 彩图、深度、红外、姿态、缓存或其他已登记材料 |
| 输出特征迁移 | 方法改变了哪些特征值和状态 |
| 失败回执 | 失败原因、影响范围、证据位置和严重程度 |
| 降级路径 | 双目失败、局部失败或性能超限时的保守输出 |
| 成本 | 平均、九十五分位、最大耗时和内存/线程成本 |
| 质量边界 | 近场、远场、遮挡、平移、局部运动等适用桶 |
| 证据要求 | 必须附带的运行包、帧、指标和审查结果 |
| 生命周期 | 探针、候选、影子、已晋级、暂停、回退 |

方法组合也必须登记。`构建全画面归簇图`属于复合方法；`写出分析特征表`和`计算运行评分`属于实验治理方法，不应与视觉认知方法混为一谈。

## 四、特征体系的修订口径

### 4.1 两类“全像素”指标

全像素归属不能只看一个覆盖率，否则把所有未知像素写成背景就会制造虚假高分。

| 指标 | 定义 | 目标口径 |
|---|---|---|
| 像素账本完整率 | 每个像素是否记录了明确的候选、背景、未知、无效或遮挡状态 | 可以追求 100% |
| 证据解决率 | 有充分证据支持的非未知像素比例 | 持续优化，不能用标签填充替代 |
| 无证据伪归属率 | 被写成确定对象但没有对应证据的像素比例 | 硬红线，目标为 0 |

因此，`Unknown` 是一种诚实的账本状态，不等于系统失败；把无证据像素伪装成背景才是更严重的失败。

### 4.2 距离与轮廓降级

双目失败只说明当前不能输出粗距证据，不说明轮廓不存在。统一降级顺序为：

```text
可靠深度
  -> 精确深度三维簇
深度不可靠但双目成功或证据可复用
  -> 粗距双目轮廓
双目失败但彩图/红外轮廓可信
  -> 纯图像轮廓，距离未知
明确存在反证
  -> 允许丢弃或归入背景/未知
```

`已丢弃`必须有原因和证据，不能把“没有双目值”本身当作丢弃理由。

### 4.3 缓存与运动

缓存复用必须同时记录：来源帧、缓存年龄、运动上下文、姿态或视觉位移、投影重叠度、对齐误差和复用结果。相机平移时不能只凭“画面变化很大”或“缓存还没过期”决定复用。

当前 `rejected motion ROI` 只是一种可复现的回放代理，不等于姿态补偿。真正的相机状态判定应使用结构化输入：

```text
来源材料页
视觉位移和时间窗
IMU角速度、加速度
相机姿态或姿态变化量
阈值与算法版本
投影重叠度和对齐误差
```

## 五、从真实失败生成需求

### 5.1 失败事件不是需求

单个 `unknown_spike`、`frame_time_spike` 或 `contour_lost_event` 只是事件。只有在相同条件下重复出现、影响达到门槛、且能排除输入无效后，才允许形成需求候选。

### 5.2 需求生成流程

```text
读取运行包
  -> 校验输入、提交、配置和帧集合
  -> 按目标主体、特征、场景和原因聚合事件
  -> 排除启动帧、传感器无效和重复报告
  -> 计算当前值、目标值和差距证据
  -> 生成需求候选
  -> 用稳定键去重
  -> 达到持续性门槛后登记为已确认需求
```

需求去重键建议由以下内容组成：

```text
目标主体 + 目标特征 + 失败类型 + 场景桶 + 触发方法版本
```

不同候选方法在相同回放中造成同类失败，默认归入同一需求；只有失败主体、特征或适用条件不同，才生成新的需求。

### 5.3 需求候选的最低证据

至少需要：

- 一个完整运行包；
- 当前基线方法、配置和提交版本；
- 失败帧或事件时间窗；
- 当前特征值和目标值；
- 对输入有效性、启动帧和数据缺失的排除说明；
- 预计会被保护的近场、远场和性能约束。

不能从一张截图、聊天描述或未审核录制直接生成已确认需求。

## 六、任务筹办与方法选择

### 6.1 任务状态迁移

```text
需求候选
  -> 已确认需求
  -> 任务筹办
  -> 练习
  -> 尝试学习
  -> 定向学习
  -> 固定回放复验
  -> 留出回放复验
  -> 在线影子验证
  -> 方法晋级 / 任务失败
```

任何阶段出现硬门槛失败、证据不完整、目标漂移或资源超预算，都应转入“任务失败”或“等待补证”，不能直接跳到下一候选。

### 6.2 方法选择顺序

任务按以下顺序选择方法：

1. 查询适用条件与需求条件相交的已晋级方法。
2. 先运行当前适用桶的基线方法。
3. 最多选择三个受控候选，每个候选只改变一个主要因素。
4. 候选按固定顺序运行，避免并发竞争污染帧耗时。
5. 候选失败后记录失败回执，再决定是否进入下一学习阶段。

不能因为某个候选总分更高，就跳过近场质量、远场保留、轮廓连续性或硬性能门槛。

## 七、练习、尝试学习和定向学习

### 7.1 练习

练习只调用已登记方法和已有参数范围，用于确认任务输入、输出、评分和失败回执链路正常。练习不能产生新的方法能力，也不能直接晋级。

### 7.2 尝试学习

尝试学习允许：

- 组合已有原子方法；
- 在登记的参数搜索空间内改变参数；
- 改变方法顺序和降级路径；
- 使用已批准的缓存、姿态或局部区域证据。

尝试学习的输出必须是可复现的候选配置和运行包，不能只保存“调参后感觉更好”。

### 7.3 定向学习

定向学习处理现有方法无法满足的明确差距。首轮只允许生成方法设计、参数契约和验证任务，不自动改写生产 C++。通过固定回放、留出回放和影子运行后，才可以进入代码实现候选。

推荐进化顺序是：

```text
自动选择已有方法
  -> 自动组合已有原子方法
  -> 学习适用条件和有限参数
  -> 人审后实现新的算法方法
  -> 通过证据后登记新版本
```

## 八、验证、晋级和回退

### 8.1 验证层次

| 层次 | 目的 | 数据 |
|---|---|---|
| 练习验证 | 确认链路和输出契约 | 已知小片段 |
| 固定回放 | 选择候选 | 参与调参的历史真实回放 |
| 留出回放 | 检验泛化 | 未参与候选选择的同类回放 |
| 在线影子 | 检验实时输入和姿态变化 | 实时 D455，结果不替换当前输出 |
| 生产启用 | 影响下一次默认选择 | 影子通过且完成晋级记录 |

固定回放只能证明“方法对历史材料有效”，不能修改当前世界事实。

### 8.2 现有硬门槛

沿用仓库当前门槛：


- `cluster_coverage_percent_p50 >= 95`；
- `unknown_percent_p50 <= 15`；
- `total_frame_ms_p95 <= 100`；
- 相对基线的 `merge_event_count` 增幅不超过 25%；
- 相对基线的 `contour_lost_event_count` 增幅不超过 25%。

ROI 相关任务增加专项门槛：

- `missing_baseline_region_count == 0`；
- `dropped_stereo_region_count == 0`；
- `contour_lost_event_count == 0`；
- 若声称“局部刷新”，应证明 ROI 未长期退化为整帧；
- G3 红线失败时，候选只能停留在探针状态。

### 8.3 晋级口径

方法不能只登记一个全局 `best`，应按适用条件登记桶：

```text
静态远场粗距
慢速相机平移
手部遮挡重现
局部运动 ROI
速度基线
```

晋级记录至少包含：方法版本、需求编号、任务编号、适用条件、保护条件、运行编号、分项指标、失败事件、审查结论和下一次选择规则。

方法可以在某个桶晋级，同时在另一个桶保持探针。`candidate_0030` 这类结果只能说明其在对应回放桶中的表现，不能自动成为全局最佳。

### 8.4 回退口径

出现以下任一条件时回退到上一个适用版本：

- 固定回放硬门槛失败；
- 留出回放出现新的轮廓丢失或误删；
- 近场精度退化超过保护范围；
- 远场保留下降；
- 在线影子出现明显错位、滞后或帧耗时尖峰；
- 证据包不完整，无法复查。

回退不是删除候选。应保留失败回执、适用条件和未满足需求，防止下一轮重复走同一条无效路径。

## 十、首轮最小验证闭环

首轮建议只验证一个主目标：真实手部遮挡—重现后的轮廓归属连续性。

### 10.1 需求模板

```text
目标主体：遮挡前后同一观察轮廓
目标特征：轮廓归属连续性
当前值：真实回放中存在丢失、错位或身份中断证据
目标值：达到已登记的连续性门槛
保护条件：近场三维不退化、远场不伪造精确距离、像素账本完整、p95不超过100ms
候选方法：当前 motion bucket 基线、有限缓存/重投影、局部证据重建并保守降级
验收材料：固定回放、留出回放、分析包和失败帧
```

### 10.2 执行顺序

```text
冻结数据、审核清单、哈希、提交和配置
  -> 用当前基线复现失败
  -> 失败不可复现则暂停需求生成
  -> 聚合事件并登记需求
  -> 练习已有方法和评分链路
  -> 顺序运行最多三个候选
  -> 用未参与选择的回放复验
  -> 通过后进入在线影子
  -> 按适用桶晋级或回退
```

如果所有候选都失败，需求保持“暂未满足”，并保留下一次任务所需的失败证据；不得为了产生赢家而放宽硬门槛。

## 十二、当前未实现项与实施边界

当前仓库尚未实现以下闭环能力：

- 自动从运行包生成去重需求；
- 需求、任务和方法的持久化登记库；
- 根据适用条件自动查询方法；
- 练习、尝试学习和定向学习状态机；
- 留出回放与在线影子结果的自动合并；
- 按适用桶自动晋级、回退和影响下一次默认选择；
- 向世界树或已确认存在体素写入的上层服务边界。

## 十三、判定“视觉能力已经进化”的证据

至少同时满足：

1. 真实失败能够形成一条去重后的需求。
2. 同一失败不会按每帧重复生成需求。
3. 任务能够查询、练习或组合已有方法。
4. 方法能够按适用条件而不是总分全局晋级。
5. 固定回放不会污染当前世界事实。
6. 晋级和回退都能追溯到需求、任务、方法版本和具体帧。
7. 下一次遇到相同条件时，系统能够选择已晋级方法。
8. 所有方案失败时，系统会保留未满足需求而不伪造成功。

这八项成立，才可以宣称“需求—任务—方法已经形成可验证的视觉能力进化闭环”。
