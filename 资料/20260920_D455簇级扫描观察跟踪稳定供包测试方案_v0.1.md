# D455 簇级扫描、观察、跟踪稳定供包测试方案

日期：2026-09-20

版本：v0.1

性质：`PixelClusterSensor` 后续实现和验收方案；本文定义拟议的 `PCS.ClusterObservation/1`，不表示该协议已经实现、已被“自我”接纳或已经形成现实存在事实。

## 1. 测试目标

建立一条可长时运行、可重放、可校验的相机供包链：

```text
原始 RGB、Depth、IR、IMU/姿态候选
  -> 帧内像素观测和分簇
  -> 相机侧短期簇跟踪
  -> 扫描 / 观察 / 跟踪定向簇级包
  -> 自我读取、校验、组织存在
```

最终目标不是“每帧输出的数字都不变”，而是：

1. 相同输入和配置必须生成可重算的相同结果。
2. 静态存在在连续帧中不应因传感器噪声反复新建、消失或换号。
3. 真实变化必须及时输出，不能为了“稳定”隐藏运动、遮挡和新目标。
4. 深度无效时降级证据类型，不伪造精确三维或把历史值冒充当前测量。
5. 全量包与增量包可重建同一相机候选状态，丢包、断流、重启不得静默变成“现场没有目标”。
6. 默认只向自我输出簇级证据；完整 RGB、Depth、IR 和逐像素数组保留在相机侧有界缓存中，按需读取。

## 2. 当前基线与未实现边界

当前 `PixelClusterSensor` 已实现 `PCS.Observation/1`，可输出完整 RGB、原始/配准深度、像素标签、归属、补全层、轮廓和帧内簇目录。它是细节观测包，不是本文所定义的自我常规输入。

当前已实现但只通过合成验证：

- `PCS.ClusterObservation/1` 严格读回、`FullSnapshot/Delta/Heartbeat` 结构校验和无损轮廓链。
- 从单帧 `PCS.Observation/1` 到 `FullSnapshot + Scan` 的无状态转换。
- 短期相机候选号、遮挡/丢失墓碑、增量状态重建。
- Python P3 影子桥：连续来源帧逐帧转换和跟踪，写出簇级包、运行清单、逐包指标和事件；合成三帧静态序列已验证首包全量、后续增量、跟踪号稳定和重建。
- 受限 `PCS.RawSequence/1` 导出：从已发布 RGBD 观察包复制彩图和原始深度，并保留实际标定、深度单位、帧号、时间戳和共同时间域；合成导出后回放已验证。
- 静态稳定性决策：对多次 P3 供包结果严格验证包、连续序号、全量加增量重建、归一化输出序列、相机跟踪号和生命周期事件；三次合成静态流已通过。归一化只排除包标识、会话标识、发布宿主时间和包含这些字段的上游观察清单 SHA256。
- 静态心跳：首帧后无簇级变化时发布空 `Heartbeat`，新增、移动、遮挡、重现和丢失仍发布 `Delta`；合成遮挡后重现已验证不会被心跳隐藏。心跳只证明供包链仍在新的源时间工作，当前协议不借此刷新每个簇的证据年龄。

当前尚未实现或未经验证：

- 扫描、观察、跟踪的定向调度和资源优先级。
- 心跳包生产、C++ 实时簇级供包接线、姿态补偿和详细材料租约。
- 真实动态回放和实机连续输入上的簇候选稳定性。
- IR/IMU 采集和导出；当前受限回放只能验证 RGBD 处理与图像空间簇候选关联，不得用于证明双目粗距或相机姿态补偿。
- 正式自我接收端 DTO、所有权、线程、接纳与回退合同。

既有动态累积回放中，慢速平移、手部遮挡和车载片段的历史复用均为 0，不得宣称已经具备动态跟踪或安全累积能力。本方案将跟踪作为新能力单独验收。

## 3. 身份与事实边界

```text
帧内簇编号
  != 相机跟踪候选编号
  != 自我确认的存在身份
```

| 对象 | 创建方 | 有效范围 | 是否可当作现实身份 |
| --- | --- | --- | --- |
| 帧内簇编号 | 相机分簇器 | 当前帧 | 否 |
| 相机跟踪候选编号 | 相机短期跟踪器 | 当前设备会话和跟踪时期 | 否 |
| 自我绑定令牌 | 自我 | 由自我的合同决定 | 相机不解释，只原样回传 |
| 存在身份 | 自我 | 世界认知合同 | 是，但不由相机生成 |

两条全局禁止性规则：

```text
未处理 != 空闲
未知 != 没有存在
```

## 4. 统一簇级数据包规格

### 4.1 传输和发布

- 协议名：`PCS.ClusterObservation/1`。
- 控制传输沿用本机 UTF-8 JSONL，日志走 stderr。
- 每份簇级包先写入未发布目录，完成长度和 SHA256 后原子改名，最后交付 `packet.json` 引用。
- JSON 保存包头、簇摘要和材料描述符；精确轮廓等可变长材料用二进制文件。
- 正常包不携带完整 RGB、Depth、IR、标签图和逐像素深度；只携带有时效、可校验的详细材料句柄。
- 首版单包 JSON 目标不超过 1 MiB，单份二进制材料不超过 16 MiB；超出预算时显式降级或失败，不静默截断。

### 4.2 包头

| 字段 | 类型/约束 | 用途 |
| --- | --- | --- |
| `格式` | 固定 `PCS.ClusterObservation/1` | 格式解析和版本门禁 |
| `包标识` | 1..128 字节唯一字符串 | 幂等读取和重复包去重 |
| `会话标识` | 设备打开后生成 | 防止跨重启误关联 |
| `跟踪时期` | 会话内单调增加的无符号整数 | 断流、标定变化或跟踪重置后隔离旧编号 |
| `输出序号` | 会话内严格递增 | 检测丢包、重复和乱序 |
| `场景版本` | 有效状态变更时递增 | 全量/增量重建 |
| `包类型` | `FullSnapshot/Delta/Heartbeat` | 状态发布方式 |
| `任务意图` | `Scan/Observe/Track/Mixed` | 说明本包的调度目的 |
| `依赖全量序号` | 增量包必填 | 防止在错误基线上应用增量 |
| `源时间` | 数值、单位、时间域 | 保留设备时间语义 |
| `发布Unix毫秒` | 宿主时间 | 发布诊断，不冒充曝光时间 |
| `结果年龄毫秒` | 已建立时钟映射时为非负数，否则 `null` | 判断证据是否过期 |
| `配置版本` | 实际生效版本 | 重放和漂移定位 |
| `标定版本` | 完整标定的可回查引用 | 几何解释 |
| `坐标系` | 具名相机/世界坐标系 | 位置和运动解释 |
| `相机姿态` | 值、来源、置信状态；不可用时为 `null` | 区分相机运动与目标运动 |
| `处理区域` | 高精度 ROI、外围扫描区、未处理区 | 防止把未处理区当作空闲 |
| `输入质量` | 流缺口、同步、预热、标定和材料完整性 | 输出可用性门禁 |
| `全局覆盖摘要` | 已处理/未知/无效/遮挡/范围外比例 | 判断本包能够说明多少画面 |

### 4.3 簇记录

| 字段组 | 必要内容 |
| --- | --- |
| 编号 | `帧内簇编号`、可空的 `相机跟踪候选编号`、可空的 `自我绑定令牌` |
| 变化 | `Added/Updated/Moved/ShapeChanged/PartiallyOccluded/Occluded/Reappeared/Lost/Removed` |
| 跟踪状态 | `Tentative/Active/PartOccluded/Occluded/Reappeared/Lost/Retired` |
| 图像空间 | XYWH 包围矩形、中心、像素数、是否触达画面边界 |
| 轮廓 | 外环、内环、闭合性、边界原因、精确材料描述符 |
| 形状 | 8x8、16x16、32x32 分级形状指纹及各自规范化规则 |
| 颜色 | 颜色空间、主色/直方图摘要、有效样本数、光照可比性 |
| 距离 | 距离模式、值或区间、不确定度、证据数量和来源 |
| 空间 | 证据允许时的三维中心、尺寸值/范围、坐标系 |
| 运动 | 上一位置、当前位置、预测位置、速度/方向候选、预测有效期 |
| 遮挡 | 未遮挡/部分/完全/疑似重现、比例及支持证据 |
| 深度证据 | 当前实测、历史候选、估算、缺失、范围外的像素数与比例 |
| 关联证据 | 轮廓相似度、IoU、颜色相似度、深度一致性、位置残差、综合置信度、竞争候选 |
| 时效 | 首次发现、最后实测、连续可见/缺失帧数、证据年龄 |
| 详细句柄 | 按需读取原始或 `PCS.Observation/1` 局部材料的有界、可过期引用 |

距离模式只允许：

```text
PreciseDepth3D
ApproxStereoContour
ImageOnlyContour
UnknownDistance
```

`PreciseDepth3D` 必须有当前可靠深度支撑；当前无可靠深度时，可保留彩图轮廓并降级为 `ImageOnlyContour`，不得仅因无双目证据丢弃轮廓。

### 4.4 轮廓紧凑编码

首版拟使用 `PCS.ContourChain8/1`：

1. 外环规范为顺时针，内环规范为逆时针；循环起点取 `(y,x)` 字典序最小点。多环按外环优先、父环、起点和面积的固定顺序写入。
2. 每个环保存起点 `(x,y)` 的两个小端 `int32`。
3. 后续每步使用 0..7 表示 8 方向相邻像素：`0=(+1,0)`、`1=(+1,+1)`、`2=(0,+1)`、`3=(-1,+1)`、`4=(-1,0)`、`5=(-1,-1)`、`6=(0,-1)`、`7=(+1,-1)`。
4. 方向码按点序每个 3 bit，从字节最低有效位开始连续打包；末尾不足一字节的高位必须为 0。
5. 环目录记录字节偏移、有效位数、点数、父环、内环、视野截断和边界原因。
6. 解码后必须与规范化后的源轮廓点列逐点一致；编码是无损压缩，不是多边形近似。
7. 不满足 8 方向相邻条件时拒绝编码，不自动改点。

### 4.5 形状指纹边界

将闭合外轮廓居中、等比缩放到 8x8、16x16、32x32 正方形，内部填充，真实内环保留为空。每级输出规范化参数、位图材料摘要和内容哈希。

精确值相等可作为候选检索，不能单独证明是同一存在。相似度、颜色、位置、深度、时间连续性和多帧重复命中必须一起进入关联证据。

## 5. 扫描、观察、跟踪三种负载

三种负载共用第 4 章的统一包头和簇记录，不定义三套事实。

### 5.1 扫描包

目的：用最小成本保持全画面覆盖并发现新变化。

必须包含：扫描区域、处理分辨率、占据/未知/无效摘要、变化 ROI、新增/消失簇候选和建议观察列表。对未变化的已知簇只发心跳或证据年龄，不重发完整轮廓。

### 5.2 观察包

目的：对一个或少量指定候选生成详细证据。

必须包含：精确轮廓、内环、分级形状指纹、颜色摘要、距离模式、深度证据分布、尺寸值/范围、置信状态和详细材料句柄。

### 5.3 跟踪包

目的：高频保持指定簇候选的时序连续性。

必须包含：跟踪候选编号、位置/预测位置、紧凑轮廓、距离变化、遮挡状态、关联证据、证据年龄和是否请求重新观察。静态外观不重复发送。

### 5.4 并行调度规则

```text
跟踪：最高实时优先级，但不可无界占用资源
观察：按自我指定的候选和截止时间分配 ROI 预算
扫描：始终保留最低全画面安全覆盖
```

高负载时允许降低外围扫描的分辨率或频率，但必须在包中显式标记降级区域、年龄和原因。不允许因跟踪一个目标而让全画面扫描消失。

## 6. 全量、增量与心跳语义

### 6.1 全量包

在会话开始、跟踪时期变化、ROI/配置/标定变化、接收方请求重同步或定期重同步时发布。包含当前可见候选和未超期的遮挡候选。

### 6.2 增量包

只包含新增、更新、移动、遮挡、重现、丢失和退役事件。增量必须声明依赖的全量序号和前置场景版本。接收方发现缺口时必须拒绝继续拼接并请求全量包。

### 6.3 心跳包

无显著变化时仍定期发布，包含源时间、输入质量、处理覆盖、活跃跟踪数和最新场景版本。心跳证明供包端仍在运行，不证明场景中没有未观测存在。

### 6.4 可重建规则

- 同一 `包标识` 必须对应同一完整内容和哈希。
- 增量只能按序号顺序应用，重复增量必须幂等。
- `Removed/Retired` 必须用墓碑记录显式发布，不得仅停止发送。
- 用一份全量包加后续全部增量重建的状态，必须与同一时点直接生成的全量状态逐字段一致，排除包标识和发布时间等明确的非决定字段。

## 7. 实现方法

### 7.1 帧内处理

1. 使用现有 `PCS.Observation/1` 进行格式、时间、标定、深度和颜色处理。
2. 从 `labels.bin`、簇目录和轮廓中构造帧内簇记录，不反向用轮廓填充替代精确标签图。
3. 计算簇的轮廓、颜色、深度证据、距离模式和形状指纹，所有比例的分母必须明确。
4. 帧内簇局部号仍按可复算规则生成，不尝试用局部号保持跨帧身份。

### 7.2 相机侧短期簇跟踪

首版采用“硬门禁 + 加权代价 + 确定性分配”：

1. 先用时间连续、姿态补偿后可达区域、中心最大位移、距离模式可比性和面积变化做硬门禁。
2. 对剩余组合计算 IoU、中心残差、形状、颜色、深度和运动一致性代价。
3. 进行全局一对一分配；代价相同时按旧跟踪号、新帧内簇号排序打破平局，保证回放可重算。
4. 一对多和多对一不直接当作身份变换；发布分裂/合并候选和竞争证据。
5. 短期缺失进入 `Occluded`，超过有界年龄进入 `Lost/Retired`。历史深度不因跟踪关联而变成当前测量。
6. 相机姿态不可用或补偿残差超限时，放弃空间重投影关联，降级为短时图像候选或重建跟踪时期。

不允许首版跟踪器自动学习新权重后直接修改生产配置。参数变更必须进入固定回放和独立验收集。

### 7.3 姿态与运动来源

运动上下文必须是结构化证据，不使用不可解析的“运动签名”。至少包含：来源帧、光流/视觉位移、IMU 角速度与加速度、姿态估计、时间窗、阈值、算法版本和置信状态。

仅有 IMU 不足以确认每个像素的对齐；必须经标定、时间同步和视觉残差复核。

### 7.4 发包器和有界队列

1. 跟踪器只更新内存中的当前候选状态。
2. 包构造器从同一不可变状态版本生成扫描、观察和跟踪负载，防止三类包相互矛盾。
3. 队列有独立数量、字节、年龄和截止时间上限。
4. 实时优先模式可以丢弃旧增量，但必须立即要求或生成新全量包，并累计准确的丢包计数。
5. 完整模式使用背压；背压导致源流缺口时明确失败，不宣称连续采样完整。

## 8. 拟议控制指令

在现有 `PCS.Control/1` 能力查询和会话门禁上增加以下指令；未实现前必须返回 `unsupported_command`：

| 指令 | 关键参数 | 结果 |
| --- | --- | --- |
| `开始扫描` | 区域、分辨率级别、最低频率、资源预算 | 建立全画面或指定区扫描任务 |
| `停止扫描` | 任务编号 | 停止指定扫描，不删除已发布证据 |
| `观察簇候选` | 跟踪号或全量序号+帧内簇号、详细级别、截止时间 | 生成一次或有界连续观察 |
| `开始跟踪簇候选` | 候选引用、可选自我绑定令牌、最长时间 | 建立高优先级短期跟踪 |
| `停止跟踪簇候选` | 跟踪候选编号 | 发布退役事件并释放预算 |
| `请求全量快照` | 预期会话和跟踪时期 | 用于初始同步和缺口恢复 |
| `读取簇级结果` | 任务编号、最多包数 | 拉取有界结果队列 |
| `读取详细材料` | 句柄、预期 SHA256、范围 | 取得指定局部原始/像素材料 |

## 9. 测试特征和指标

### 9.1 协议与证据正确性

| 特征 | 计算方法 | 硬门禁 |
| --- | --- | --- |
| 包验证通过率 | 合法包/已发布包 | 100% |
| 材料摘要通过率 | 长度和 SHA256 都正确的材料/全部材料 | 100% |
| 输出序号可解释率 | 连续或有明确缺口事件的包/全部包 | 100% |
| 增量重建一致率 | 全量+增量状态与直接全量状态比较 | 100% |
| 越权精确深度数 | 无当前可靠证据却输出 `PreciseDepth3D` | 0 |
| 世界身份越权数 | 相机自行创建或确认存在身份 | 0 |
| 未处理误写空闲数 | 未处理/未知区被写成空闲 | 0 |

### 9.2 确定性和状态稳定性

| 特征 | 初期验收值 |
| --- | ---: |
| 同回放、同配置顺序运行 3 次，归一化后的包哈希一致率 | 100% |
| 静态 600 帧中主候选跟踪号切换数 | 0 |
| 静态预热后虚假 `Lost/Reappeared` 事件数 | 0 |
| 静态主候选连续关联率 | >= 99.5% |
| 静态主候选归一化填充轮廓相似度 p50 | >= 99% 目标；不达标先报告分布，不通过扩大容差修改原观测 |
| 轮廓中心位置抖动 p95 | 首轮建立基线；不得用锁死输出获得假稳定 |
| 距离模式无原因往复切换数 | 0 |

归一化确定性比较只排除包标识、发布宿主时间、随机会话字符串和文件绝对路径。源帧、簇顺序、跟踪分配、轮廓、证据值、事件和材料内容不得被排除。

### 9.3 扫描、观察和跟踪专项指标

| 负载 | 主要指标 |
| --- | --- |
| 扫描 | 全幅覆盖率、未处理显式标记率、新变化发现延迟、扫描年龄 p95/max、新候选漏报/误报 |
| 观察 | 指定候选命中率、详细材料完整率、轮廓/内环一致性、深度证据分账正确性、请求到包延迟 |
| 跟踪 | 跟踪连续率、ID 切换、遮挡后重现候选率、误合并/误分裂、位置误差、证据年龄、退役及时性 |
| 混合 | 跟踪延迟、观察完整性、最低扫描覆盖是否同时满足，是否出现资源饥饿 |

### 9.4 性能和长时运行

以下均需报告 p50、p95、p99 和 max：

- 采集、帧内分簇、关联、轮廓压缩、包构造、材料写入和队列等待耗时。
- 从源时间到可读取包的结果年龄；时钟不可比时为 `null`，不用处理耗时代替。
- 队列深度、最旧包年龄、丢弃/背压次数、重同步次数。
- CPU、内存、每分钟写入字节和详细材料缓存使用量。

簇级生产候选最终仍应满足当前项目 `total_frame_ms_p95 <= 100ms` 硬门禁。在协议和算法早期阶段可先记录不混合评分，但不得在晋级时忽略延迟。

## 11. 分阶段实现与验收

### P0：冻结簇级协议

实现：JSON Schema/严格验证器、枚举、长度上限、轮廓编码器/解码器、合成正反例。

退出条件：T0 全部通过；未知字段、非法状态转移、越界材料和摘要不符必须被拒绝。

### P1：从 `PCS.Observation/1` 转换为无跟踪簇级全量包

实现：帧内簇摘要、距离模式、形状指纹、紧凑轮廓、详细句柄。

退出条件：同帧簇级包能反向核对原标签簇目录；相同回放 3 次归一化后一致。

### P2：短期簇跟踪和全量/增量发布

实现：候选关联、状态机、遮挡期限、墓碑、重同步、心跳和直接快照对照器。

退出条件：T1、T2、T9 通过；增量重建一致率 100%；静态主候选无 ID 切换和虚假丢失/重现。

### P3：扫描、观察、跟踪定向负载

实现：控制指令、ROI/外围覆盖、优先级调度、资源预算和混合负载指标。

退出条件：T3、T7、T10 通过；跟踪和观察负载不得使最低全幅扫描消失。

### P4：姿态补偿和动态场景

实现：姿态/视觉位移结构化证据、短时重投影、不可用降级和动态边界验收。

退出条件：T4、T5、T6、T8 通过；不通过时保留候选或降级距离，不伪造连续性。

### P5：长时稳定性和自我影子接入

实现：至少 2 小时实时运行、反复开闭、消费者慢/断开/恢复、详细材料过期、内存/磁盘上限和自我只读影子消费。

退出条件：无无界内存/磁盘增长；无无法解释的序号缺口；恢复后通过全量包重建；影子接收者不影响相机主链。

### P6：正式采用评审

必须另行确认自我侧 DTO、材料所有者、启动接线、线程、超时、幂等、回退和存在接纳合同。P5 通过不等于正式业务采用。

## 12. 每次运行的标准证据包

每次测试至少生成：

```text
cluster_test_runs/<run_id>/
  run_manifest.json
  config_snapshot.json
  dataset_manifest.json
  packets.jsonl
  packet_metrics.csv
  cluster_metrics.jsonl
  track_metrics.csv
  events.csv
  reconstruction_report.json
```

`run_manifest.json` 必须记录 Git 提交、构建类型、硬件、SDK、输入哈希、命令行和开始/结束状态。`run_decision.json` 分开记录协议、确定性、静态、动态、证据边界和性能门禁，不用一个总分补偿硬失败。

真实录制、原始包和大体量详细材料不自动提交或上传；仓库只保存协议、工具、清单、聚合指标、最小反例和决策记录。

## 13. 通过、降级和停止规则

只有以下条件全部满足，才能声明“可持续稳定向自我输出簇级数据包”：

1. 协议、材料和增量重建硬门禁全部通过。
2. 同回放确定性通过，静态场景无跟踪换号和虚假生命周期事件。
3. 遮挡、平移、车载和多目标场景的失败能显式降级，不冒充当前精确观测。
4. 扫描、观察、跟踪并行时，全画面最低扫描覆盖仍然存在。
5. 长时运行无无界资源增长，可从丢包、断流和消费者重启中重同步。
6. 自我侧只读影子验证通过，且正式接纳合同已单独冻结。

任一下列情况必须降级或停止晋级：

- 没有当前深度证据却输出精确三维。
- 丢失增量后仍在旧状态上继续拼接。
- 会话或跟踪时期改变后复用旧跟踪号。
- 把“无证据”、“未处理”或“包未到达”写成场景空闲。
- 为保持 ID 稳定而忽略真实新目标、分裂、合并或移动。
- 把固定回放中的高分直接写成当前场景事实。

## 14. 首轮执行顺序

1. 把第 4、6 章转写为 `PixelClusterSensor/PROTOCOL.md` 的可实现规范，同时增加严格验证器和合成反例。

这一顺序先冻结自我可读取的事实边界，再测定性能，可避免在尚不能安全重建状态时就开始调优延迟。
