# D455 32x32轮廓精确值检索与多帧存在确认分析报告 v0.1

## 一、结论

本报告对“保存足够多的32x32轮廓值后，能否用值相等查找并确认有限场景中的存在”进行阶段判断。结论如下：

1. 在场景成员封闭、轮廓算法版本固定、每个精确值经过跨存在排他验证的条件下，32x32精确值可以作为“场景内唯一轮廓键”。唯一键命中同一存在多次后，可以确认该场景中的存在身份。
2. 精确值命中适合作为第一层快速检索。32x32二值轮廓只有1024 bit，即128 byte；使用哈希索引时平均查询复杂度接近 `O(1)`，明显低于对全部候选逐一计算IoU的 `O(N)` 路径。
3. 当前570帧不足以覆盖所有存在的完整精确值集合。第一段 ID 5 的570帧产生558种值，末尾多个窗口仍有96%-97%的新值，说明其取值空间尚未收敛。
4. “样本不足”不是当前数据的唯一结论。现有样本已经足以确认：第一段 ID 1 存在明显的精确重复结构，而ID 5在当前静态处理口径下几乎每帧产生一个新值；两者具有真实的观测稳定性差异。
5. 精确值命中具有“高精度、低召回”的潜力：经过验证的唯一值一旦命中，可以提供很强的身份材料；但ID 5的大量新值会让许多帧无法命中已有字典。
6. 当前正确生产路线不是在精确值和相似度之间二选一，而是“精确值优先、相似度回退、时空证据确认、确认后扩充值集合”。

推荐流程固定为：

```text
32x32精确值哈希查询
→ 唯一命中：累计多帧一致证据
→ 歧义命中：结合位置、尺寸、距离、运动和历史复核
→ 未命中：粗级筛选后计算32x32 IoU
→ 联合证据确认：把新值登记到该存在
```

## 二、测试问题与边界

本报告回答四个问题：

1. 570帧产生大量不同值，是否只能说明样本不够？
2. 保存足够多的值后，能否在有限场景中用精确值确认存在？
3. 是否可以通过多帧多次命中降低单帧误判？
4. 精确值比较和相似度比较哪个更快，应如何组合？

本报告不宣称：

- 当前32x32值是现实世界全局唯一身份证；
- 当前数字 `contour_id` 已经等于人工确认的现实存在身份；
- 570帧已经覆盖任一存在的完整可达轮廓值空间；
- 当前复杂度判断已经等同于C++生产路径实测耗时。

## 四、精确值重复与样本收敛

### 4.1 统计结果

| 回放与ID | 帧数 | 不同值 | 重复帧数 | 单例值 `f1` | 双例值 `f2` | 任意两帧精确碰撞率 | 相邻帧精确重复率 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 第一段 ID 1 | 570 | 170 | 400 | 99 | 24 | 3.059846% | 3.163445% |
| 第一段 ID 5 | 570 | 558 | 12 | 548 | 9 | 0.009250% | 0% |
| 第二段 ID 5 | 570 | 559 | 11 | 551 | 6 | 0.009250% | 0% |

“重复帧数”按 `总帧数 - 不同值数` 计算。任意两帧精确碰撞率按同一track中所有无序帧对统计，不等于相邻重复率。

### 4.2 末尾窗口新增值

“新增值率”定义为末尾窗口中首次出现、且此前所有帧均未出现过的不同值数量，占窗口帧数的比例。

| 回放与ID | 最后50帧 | 最后100帧 | 最后200帧 |
|---|---:|---:|---:|
| 第一段 ID 1 | 30% | 21% | 24% |
| 第一段 ID 5 | 96% | 96% | 97% |
| 第二段 ID 5 | 98% | 98% | 97% |

判断：

- ID 1 已出现明显重复结构，但新值仍在产生，尚不能宣布完整收敛。
- 两段ID 5的唯一值曲线仍接近线性增长，570帧明显不足以覆盖其可达值集合。
- 增加样本会增加重复总数，但也可能继续以很高比例产生新值，不能预设最终一定收敛为很小的模板集合。

### 4.3 探索性未见值估计

使用 `Chao1 = 已见不同值数 + f1^2 / (2*f2)` 做探索性估计：

| 回放与ID | Chao1探索性估计 |
|---|---:|
| 第一段 ID 1 | 约374.2种 |
| 第一段 ID 5 | 约17241.6种 |
| 第二段 ID 5 | 约25859.1种 |

ID 5的单例值占比过高，Chao1数值非常不稳定，不能当作真实上限。它只提供一个方向性信号：ID 5仍处于严重欠采样阶段。

因此，正确结论是：

> 当前样本不足以估计ID 5最终会产生多少种值，但已经足以否定“所有静态存在都会稳定地产生少量固定32x32精确值”这一假设。

## 五、有限场景中的唯一值确认

### 5.1 场景内唯一轮廓键

只有同时满足以下条件，精确值才可标记为“场景内唯一轮廓键”：

1. 场景中的存在集合已经登记，测试期间没有未登记存在进入。
2. 该精确值在训练材料和独立验收材料中只绑定一个存在。
3. 轮廓算法、特征版本和相机处理口径固定。
4. 产生该值的当前轮廓没有已知合并、分裂或严重遮挡。
5. 哈希命中后继续核对完整128 byte，排除哈希碰撞。

可将索引定义为：

```text
(场景版本, 特征算法版本, 32x32位图哈希)
→ 一个存在ID：唯一键
→ 多个存在ID：歧义键
→ 无记录：新值
```

“数据库中当前只有一个绑定”不自动等于已经证明唯一。若其他存在尚未充分采样，该值仍可能在后续发生跨存在碰撞。

### 5.2 当前碰撞证据

当前两段各自内部的不同数字ID之间，32x32精确碰撞值均为0。这支持32x32进入场景内唯一键实验，但不能证明未来或其他场景仍为0。

跨两个回放比较时，不同数字ID之间存在135个共享精确值：

| 第一段ID | 第二段ID | 共享精确值 |
|---:|---:|---:|
| 10 | 9 | 88 |
| 9 | 8 | 47 |

这更可能表示两个回放中的数字ID发生重新编号，说明 `contour_id` 不能直接当作跨回放现实身份。后续唯一键验收必须使用独立的现实存在标签，而不是只比较数字ID。

## 六、多帧多命中确认

精确唯一值命中可以提供强证据，但多帧确认可以抵抗单帧分割异常、临时轮廓合并和偶然错误绑定。

建议状态机：

```text
首次唯一值命中
→ 存在候选

最近5个有效帧中至少3次指向同一存在
→ 稳定确认

最近8个有效帧中至少5次指向同一存在
→ 高可信确认

命中另一个存在的唯一值
→ 发生冲突，降回候选并重新累计
```

只有满足以下条件的帧才计入有效命中：

- 当前轮廓来自新处理帧，不是缓存结果重复显示；
- 轮廓位置、尺寸和运动关系连续；
- 没有明显合并、分裂或失配事件；
- 相机运动时已经完成必要的姿态补偿或投影一致性检查。

多个不同精确值分别指向同一存在，比同一个精确值连续重复更强。相邻帧高度相关，因此“连续三帧相同”不能按三个完全独立证据计算；验收时还应记录时间跨度和不同值数量。

## 七、精确比较与相似度比较的效率

### 7.1 算法成本

一条32x32二值轮廓可表示为16个 `uint64`。

精确值索引路径：

```text
计算16个uint64的哈希
→ 哈希表平均O(1)查询
→ 对少量命中项做128 byte完整相等校验
```

IoU路径对每个候选至少需要：

```text
16次按位AND
+ 16次按位OR或等价运算
+ popcount与累加
+ 交集/并集比例计算
```

若字典中有 `N` 个候选值，直接逐项计算IoU的成本为 `O(N)`。精确比较还可以在首个不同字后提前停止，IoU必须完成交集和并集统计。因此，在候选规模增长时，哈希精确检索明显更适合作为第一层。

以上是算法复杂度判断，不是当前D455 C++主循环的实测耗时。进入生产前仍需补充固定CPU、固定字典规模下的查询延迟基准。

### 7.2 推荐分层索引

```text
第一层：32x32精确哈希
  唯一命中 → 多帧确认
  歧义命中 → 进入联合复核

第二层：8x8或16x16粗特征
  只用于缩小候选集合

第三层：32x32 IoU
  只比较粗筛后的少量候选

第四层：位置、尺寸、距离、运动、遮挡和历史
  裁决旧存在、接替track、新存在候选或未知
```

确认新值属于某个旧存在后，可将该值登记到其字典。这样精确字典会把越来越多的相似度回退转换为快速直接命中。

## 八、精度、召回与存储的关系

### 8.1 精确值命中的意义

经过排他验证的唯一值命中，可以具有很高的场景内确认精度；但它不保证高召回率。ID 5的当前结果说明，即使字典已经保存数百个值，下一帧仍很可能产生未见值。

### 8.2 字典增长

32x32原始位图每条128 byte：

| 条目数 | 仅位图原始大小 |
|---:|---:|
| 10000 | 约1.22 MiB |
| 100000 | 约12.21 MiB |
| 1000000 | 约122.07 MiB |

实际哈希表还需要哈希、存在ID、版本、统计和容器开销。存储本身在中等规模下可控，但精确值数量持续线性增长时，需要通过版本、存在和场景分桶，不能把所有值放进无边界的全局表。

### 8.3 歧义增长

保存值越多，已见状态的精确召回会提高；同时，不同存在之间发现共享值的概率也会上升。共享值必须从“唯一键”降级为“歧义键”，不能继续直接确认任何一个存在。

## 九、下一轮长时测试

建议把同一静态场景扩展到5000-10000帧，按每500帧一个窗口记录：

```text
累计帧数
累计不同值数
窗口新增不同值率
单例值和双例值比例
相邻精确重复率
随机帧对精确碰撞率
精确字典在后续留出帧上的命中率
唯一命中、歧义命中和未命中数量
```

探索性收敛门槛可先定义为：连续5个500帧窗口的新增不同值率均低于1%。如果ID 5在5000-10000帧后仍接近线性增长，就不再以“完整枚举精确值集合”为目标，而把精确值限定为高可信快速命中缓存，主要召回由模板簇和IoU承担。

还需要补充两类验收：

1. 使用未参与建库的后续帧，测量精确值字典的真实命中率和确认延迟。
2. 使用人工登记的现实存在标签，测量唯一键跨存在误绑定率，不能继续以数字 `contour_id` 代替真值。

## 十、实现建议

建议的数据结构：

```text
轮廓值记录：
  场景版本
  特征算法版本
  32x32完整位图
  64位或128位哈希
  绑定存在ID集合
  首次和最近命中帧
  独立命中次数
  是否唯一
  是否通过留出材料验证

存在确认状态：
  未知
  候选
  稳定确认
  高可信确认
  冲突待复核
```

新增精确值时，不应仅凭单帧最高IoU自动写入存在字典。至少要求形状相似度、位置/尺寸/距离连续性和多帧track关系共同通过，避免错误学习持续污染后续精确命中。

## 十一、最终判定

当前路线成立，但需要限定口径：

```text
有限封闭场景
+ 已审核存在集合
+ 固定32x32特征版本
+ 经过排他验证的场景内唯一值
+ 多帧一致命中
= 可以确认场景内存在
```

当前最合理的能力定位为：

```text
精确值哈希：最快第一层索引和高可信命中材料
32x32 IoU：精确未命中后的近似召回
多帧时空证据：最终确认和新值入库门禁
```

570帧确实不足以枚举ID 5的全部值，但现有数据已经证明不同存在的精确值复现能力差异很大。下一步不应只等待“终于重复”，而应测量唯一值累积曲线是否进入平台，以及精确字典对独立后续帧的实际召回率。
