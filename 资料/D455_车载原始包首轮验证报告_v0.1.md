# D455 车载原始包首轮验证报告 v0.1

## 一、阶段结论

本轮使用真实移动车辆中的 D455 原始 `.bag`，完成了传感器流完整性检查、连续目录回放派生、`candidate_0030` 三段连续窗口复跑、评测语义修订和代表帧视觉复核。

结论分为四层：

1. **原始材料可用于后续研究，但不是无缺口材料。** 彩图、深度、左右红外、陀螺仪和加速度流全部存在且时间戳单调；深度估计缺 11 帧，左右红外各估计缺 14 帧，最大间隔分别达到约 390 ms 和 490 ms。
2. **`candidate_0030` 在三个连续 120 帧窗口中通过当前硬门槛。** 覆盖率 p50 为 100%，未知比例 p50 为 0%，轮廓丢失、合并、分裂和超过 100 ms 的帧均为 0；p95 为 48.66-54.82 ms。
3. **硬门槛通过不等于空间分割质量已经合格。** 三段的 `PreciseDepth3D` 像素 p50 均为 0%，排除 `FarBackground` 后的证据解决率只有 26.00%-29.83%，约 69.22%-74.20% 的画面由 `FarBackground` 兜底。
4. **彩图轮廓双目粗距尚未形成可信几何证据。** 35 秒和 50 秒窗口的直接 stereo 全部失败；5 秒窗口唯一结果长期复用同一个天空/树线区域，估距 18.24 m、估宽 22.088 m。当前实现直接把彩图 ROI 用到左右红外图，并在目录回放中使用合成内参，因此不能把该结果解释成可靠距离。

所以，本轮证明的是：

> 原始车载材料已接入确定性验证链，像素账本和当前性能硬门槛可通过；但近场三维证据、对象级分割质量和彩图到双红外的几何一致性仍未通过验证。

## 五、评测语义修订

本轮发现旧评分把一个方法的失败错误升级为目标证据缺失：

```text
彩图轮廓直接 stereo 失败
旧口径 -> 远场粗距完全缺失并扣分
正确口径 -> 先检查是否仍有深度区间证据
```

因此拆分为：

| 特征 | 含义 | 是否直接扣空间/远场分 |
| --- | --- | --- |
| `far_stereo_failed` | 彩图轮廓直接 stereo 方法没有得到距离 | 否，只保留诊断 |
| `far_distance_evidence_cluster_count` | 有正数深度区间或 stereo 距离的远场簇数 | 用于判断证据存在 |
| `far_distance_missing` | stereo 与深度区间两种粗距都不存在 | 是 |

运行时 `color-contour-refresh-on-far-loss` 同步采用证据级定义。修订前，35 秒和 50 秒窗口各出现 7 次 far-loss 刷新，并产生大量 cooldown skip；修订后，三个窗口均只保留 1 次启动刷新，far-loss 刷新和 cooldown skip 都为 0。已有 `far_depth_interval` 时不再重复提交全图 stereo 刷新。

## 七、像素账本与证据解决率

`cluster_coverage_percent = 100%` 只表示每个像素都被登记为某种模式，不表示每个像素都有充分几何或对象证据。

本报告使用以下临时解释辅助审查：

```text
证据解决率 =
(PreciseDepth3D + ApproxStereoContour + ImageOnlyContour
 + BackgroundPlane + DepthHoleCandidate) / total_pixels

不把 Unknown 和 FarBackground 兜底计为已解决证据。
```

| 窗口 | PreciseDepth3D | ApproxStereoContour | ImageOnlyContour | FarBackground | 证据解决率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 005s | 0.00% | 17.72% | 8.28% | 74.20% | 26.00% |
| 035s | 0.00% | 19.19% | 10.64% | 69.22% | 29.83% |
| 050s | 0.00% | 18.11% | 9.13% | 73.01% | 27.24% |

这说明当前 100% coverage 主要来自完整账本和 `FarBackground` 降级，而不是高比例精确三维簇。

## 八、视觉复核

复核了三个窗口的 `cluster_map_frame_000105_overlay.png` 和 `final_segmentation_frame_000105_overlay.png`。

可见特点：

- 道路、天空、树木和隔离设施能形成大范围归属区域。
- 部分车辆边界能被彩图或远场区间覆盖，但对象级轮廓并不稳定地逐车分离。
- 多个区域过大，存在天空/树线、路面和相邻对象被宽泛归属的现象。
- 最终彩图分割中的缓存区域与当前场景并未形成足够强的逐帧对齐证据。

因此，本轮分数不能替代逐对象真值、轮廓 IoU、身份连续性和距离误差验证。

## 九、彩图双目粗距的主要风险

当前 `estimateStereoContourDistances()` 的关键流程是：

```text
彩图分割得到 region.roi
-> 同一个 ROI 直接裁左 IR
-> 扩展后直接裁右 IR
-> 模板匹配得到视差
-> 使用传入内参计算距离和尺寸
```

这里存在两个尚未闭合的坐标语义问题：

1. `region.roi` 属于彩图坐标系，却直接用于原始左/右 IR。彩图与双红外存在不同内参、外参和视场，像素坐标不能直接等同。
2. 目录 replay 目前通过 `makeReplayIntrinsics()` 构造合成内参，没有从原始包 manifest 读取真实 color/IR 内参和外参。

5 秒窗口唯一 stereo 结果为：

```text
bbox = [175, 0, 465, 21]
estimated_distance_mm = 18240
estimated_size_mm = [22088, 998]
median_disparity_px = 2.0
matched_stereo_points = 36
```

该区域横跨画面顶部的大范围天空/树线，而且同一结果从 frame 0 缓存复用到 frame 105。它只能证明当前函数产生了一个数值，不能证明该数值对应正确现实对象。

## 十、本轮已确认与未确认

### 已确认

- 原始 `.bag` 含完整流类型和可用时间戳。
- 原始材料可以派生为当前目录 replay，且不修改原包。
- 三段连续窗口均能完成 D455、converter、score 全链路。
- 当前像素账本覆盖和 100 ms 硬门槛通过。
- 深度区间证据存在时，不应把直接 stereo 失败记为远场距离完全缺失。
- 证据级 far-loss 判定能消除本轮重复刷新和 cooldown 抖动。

### 未确认

- 近场 `PreciseDepth3D` 是否在车载视角中正确产生。
- 车辆、行人、护栏、路面等对象是否被正确逐对象分离。
- stereo 距离和尺寸是否几何正确。
- 目录 replay 的三维尺寸是否可信，因为仍使用合成内参。
- 只在启动时刷新彩图轮廓能否长期跟随车辆运动；当前 120 帧窗口内缓存年龄过长，可能出现视觉滞后。
- 原始包长缺口附近的深度/IR 降级行为是否正确。

## 十一、下一步优先级

1. **保存真实标定。** 原始 bag 派生 manifest 写入 color、depth、left IR、right IR 的内参，以及相关外参和深度比例；目录 replay 必须读取这些值。
2. **修正彩图到 IR 的坐标链。** 可选择“彩图 ROI 经外参和深度先验映射到左 IR”，或“先在左 IR 独立提取轮廓并做双目，再映射回彩图”；不能继续把彩图像素坐标直接当作 IR 坐标。
3. **建立对象级质量门禁。** 对车辆等审查对象增加轮廓完整率、漏检、误合并、误分裂、中心漂移和粗距顺序真值，避免 `FarBackground` 兜底掩盖分割失败。
4. **增加缓存时效门禁。** 记录缓存年龄、姿态/视觉运动补偿后的重投影误差和对齐 IoU；证据级 far-loss 不再触发时，必须由 motion、最大年龄或对齐失败触发更新。
5. **验证长缺口。** 从约 390-490 ms 缺口附近派生连续窗口，确认缺流帧的显式降级和事件记录。

在完成前两项之前，不应继续围绕 stereo 阈值调参，也不应把 5 秒窗口的 18.24 m 结果作为候选晋级依据。
