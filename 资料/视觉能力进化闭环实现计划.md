本计划把《视觉方法需求—任务—学习—晋级闭环详细设计》落成可执行工程流程，不把当前候选结果直接宣布为新的生产能力。

完成条件是：真实失败能生成去重需求；需求能筹办成单目标任务；任务能查询和执行适用方法；固定回放、留出回放和影子验证能分层；失败候选不能晋级；晋级和回退能追溯；下一次相同条件能选择已晋级方法；全部失败时保留未满足需求。

## 二、范围与排除

### 本计划包含

- 需求、任务、方法、晋级和回退的机器可读记录；
- 从 `analysis_runs` 指标和事件生成需求候选；
- 需求去重、持续性判断和证据引用；
- 任务筹办、适用方法查询、候选回放和结果汇总；
- 固定回放、留出回放、在线影子的门禁；
- 按场景桶更新 `configs/best/` 和下一次方法选择。

### 首轮明确排除

- 不批量重命名 C++ 函数和变量；
- 不自动生成或修改生产 C++ 算法；
- 不把历史回放写入当前世界事实或已确认存在体素；
- 不把无证据 `Unknown` 填充成背景；
- 不把硬门槛失败候选写入 `best`；
- 不把同一视频的相邻帧切片当作独立泛化验证；
- 不接入世界树、场景体素或外部控制面板。

| 阶段 | 目标 | 主要产物 | 是否改 `D455.cpp` | 门禁 |

## 四、P0：冻结实现契约

### 目标

将设计概念转成机器可校验字段，区分“内部函数、正式方法、候选方案和运行评分”。

### 计划文件

```text
eval/visual_evolution/schema.json
eval/visual_evolution/README.md
```

记录类型为：需求、任务、方法、晋级、回退。字段至少包括：

```text
需求：编号、目标主体、目标特征、当前值、目标值、差距证据、去重键、保护条件、状态
任务：编号、来源需求、单一主目标、基线方法、候选方法、输入材料、预算、验证合同、回退条件、状态
方法：编号、版本、适用条件、输入证据、输出迁移、失败回执、降级路径、成本、生命周期
晋级：方法版本、适用桶、需求、任务、固定回放、留出回放、影子结果、保护条件、原因
```

已有分析协议文件和字段保持兼容，不改原有语义。

### P0 门禁

- 缺少编号、版本、状态或证据引用的记录必须被拒绝；
- 需求不能把“指定实现方法”作为主字段；
- 一个任务只能有一个主目标；
- 方法必须声明失败回执和降级路径；
- 晋级必须引用真实运行包。

## 六、P2：从失败运行生成需求

### 计划脚本

```text
scripts/derive_visual_requirements.py
```

脚本读取标准分析包，默认只输出 `requirement_candidates.json`，不自动写正式需求库。只有显式 `--register` 才允许登记。

处理顺序：

```text
校验运行包
  -> 排除启动帧、无效输入和缺失指标
  -> 聚合轮廓丢失、未知突增、帧耗时超限、远场丢失、ROI过大和G3事件
  -> 计算当前值、目标值、发生帧、持续时间和基线差距
  -> 使用稳定去重键合并
  -> 输出需求候选或证据不足说明
```

默认去重键：

```text
目标主体 + 目标特征 + 失败类型 + 场景桶 + 触发方法版本
```

### P2 首轮验收

使用真实 `hand_occlusion_reappear` 运行，确认能形成“遮挡重现后轮廓归属连续性”候选，包含运行编号、事件帧和保护条件；同一事件不得按帧重复；不能把 `candidate_0035` 的 G3 通过误写成“ROI 已可生产”。

## 七、P3：任务筹办和方法选择

### 计划脚本

```text
scripts/prepare_visual_task.py
scripts/select_visual_methods.py
```

任务规则：

- 主目标只能一个，近场、远场、性能和 G3 是保护条件；
- 先选择适用桶中最近的已晋级基线；
- 最多三个受控候选，每个候选只改变一个主要因素；
- 每个候选必须声明预期改变的特征、风险和降级路径；
- 无适用方法时进入定向学习待筹办，不能直接复用其他场景冠军。

首轮受控对照为：`candidate_0030` 基线、`candidate_0034` direct-build 探针、`candidate_0035` direct-build/drop 探针。后两个保持 probe-only。

## 九、P5：固定回放、留出回放和回归门禁

### 计划改动

扩展或新增：

```text
scripts/compare_runs.py
scripts/evaluate_visual_task.py
scripts/select_winners.py
eval/score_weights.yaml
eval/cases.yaml
```

`compare_runs.py` 当前只输出分数差异，计划扩展为输出：

```text
regression_status = pass | fail | insufficient_evidence
hard_gate_status = pass | fail
near_protection = pass | fail
far_protection = pass | fail
performance_protection = pass | fail
```

沿用当前硬门槛：`cluster_coverage_percent_p50 >= 95`、`unknown_percent_p50 <= 15`、`total_frame_ms_p95 <= 100`，合并事件和轮廓丢失事件相对基线增幅不超过 25%；ROI 任务还必须通过 G3。`pass=false` 运行不得进入 winner、pareto 或 promotion。

### 数据分割

```text
练习：已有 hand_occlusion 回放，用于链路调试
验证：未参与候选选择的同类遮挡重现回放
保护：slow-pan 和近/远/深度孔洞固定 case
影子：实时 D455，结果不替换当前输出
```

如果只有一段 `hand_occlusion_reappear`，只能完成链路演练，不能宣称泛化或晋级；不能用相邻帧切片冒充独立留出集。

## 十、P6：按适用桶晋级、回退和下一次选择

### 计划脚本

```text
scripts/promote_visual_method.py
scripts/rollback_visual_method.py
scripts/select_applicable_method.py
```

晋级命令必须显式接收任务、方法版本、适用桶、固定回放、留出回放和影子运行。只有固定回放、留出回放、保护条件和必要的影子结果全部通过，才允许写入 `promotions.jsonl` 并更新对应 `configs/best/`。

回退只撤销某个适用桶的当前选择，不删除候选或失败证据。回退记录必须包含替换方法、触发运行、失败指标、失败帧、原因和下一步任务。

下一次方法选择依据：

```text
场景桶 + 运动状态 + 距离/证据状态 + 资源预算 + 方法生命周期
```

只返回已晋级且条件匹配的方法；无匹配时返回基线或“无适用方法”，不能默认选择总分最高的失败候选。

## 十三、风险与停止条件

### 主要风险

- 单帧噪声被误判为稳定需求；
- 不同目标被事件聚合错误合并；
- 一个任务用总分掩盖多个目标退化；
- 训练/验证/测试数据泄漏；
- 失败候选进入 `configs/best/`；
- 缓存滞后或姿态错位没有进入事件表；
- 记录库与英文分析协议出现两套冲突事实。

### 停止条件

运行包缺失、需求没有稳定差距、没有适用基线、无法区分测试集、触发 G3 红线、评分器与运行包字段不一致、C++ 构建或回放命令失败时，停止当前阶段并保留证据。
